# Mode: /goal (Persistent Execution and Acceptance)

Use for `/goal` or sustained execution through completion. Apply the [main task loop](../SKILL.md#auxiliary-command-modes).

- Keep taking useful action toward the requested outcome, including diagnosis, repair, and alternative approaches. Choose retries by progress, new evidence, expected benefit, and cost; there is no fixed attempt limit or mandatory repair sequence.
- Select verification that demonstrates the outcome: automated checks when appropriate, artifact or source evidence when those better fit the deliverable. Passing commands support acceptance but do not replace checking the result.
- Adjust checks as the task develops while preserving the intended behavior. Distinguish failures, unavailable checks, and verified results.
- Finish when the requested outcome is supported by sufficient evidence. When meaningful progress needs an unavailable input, decision, or capability, state the unfinished work and what would enable it; user redirection or cancellation changes the goal.
